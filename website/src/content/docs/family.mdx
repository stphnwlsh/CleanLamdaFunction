All five Clean templates share the same Application and Infrastructure layers, the same tests and the same pipeline. Only Presentation changes.

<Family />

| Template | Presentation | Use it when | Package |
| --- | --- | --- | --- |
| [Clean Minimal API](https://github.com/stphnwlsh/CleanMinimalApi) | ASP.NET Core Minimal APIs | You want a lean HTTP API | [CleanMinimalApi.Template](https://www.nuget.org/packages/CleanMinimalApi.Template) |
| [Clean Web API](https://github.com/stphnwlsh/CleanWebApi) | ASP.NET Core controllers | You like your HTTP API with classes and attributes | [CleanWebApi.Template](https://www.nuget.org/packages/CleanWebApi.Template) |
| [Clean GraphQL API](https://github.com/stphnwlsh/CleanGraphQLApi) | Hot Chocolate | Your clients want to ask for exactly what they need | [CleanGraphQLApi.Template](https://www.nuget.org/packages/CleanGraphQLApi.Template) |
| [Clean Model Context Protocol](https://github.com/stphnwlsh/CleanModelContextProtocol) | MCP server | You want AI assistants to use your app as a tool | [CleanModelContextProtocol.Template](https://www.nuget.org/packages/CleanModelContextProtocol.Template) |
| **Clean Lambda Function** | AWS Lambda | You want a serverless function on AWS | [CleanLambdaFunction.Template](https://www.nuget.org/packages/CleanLambdaFunction.Template) |

<p class="cl-aside-quip">One logo covers all five. Its four rings follow the Clean Architecture diagram: the casing for frameworks and drivers, the coils for the interface adapters (all the different ways in), the ring for the use cases, and the entities in the core. Any resemblance to a superhero's chest piece is purely coincidental.</p>
