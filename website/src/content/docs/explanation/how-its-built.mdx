These are templates I build for fun, but the pipeline doesn't know that. Every pull request goes through the same checks, and some of them are allowed to say no.

**Gatekeepers** fail the build and block the merge. **Tattletales** report what they find and leave the decision to a human.

## The rules on main

- Every change goes through a pull request, and every check above must pass.
- Only the maintainer can merge. Pull requests from anyone are welcome, but the green button has one owner.
- Commits must be signed, and merges are squashed so the history stays readable.
- Release tags can't be moved or deleted once they exist, so a version always means the same code.
- Third-party GitHub Actions are pinned to a commit, not a tag, so nobody can swap them out from under us.

## Releases

New versions go to [NuGet](https://www.nuget.org/packages/CleanLambdaFunction.Template) on the 1st of each month, but only when something outside the `.github` and `website` folders has changed. Publishing uses NuGet [trusted publishing](https://learn.microsoft.com/nuget/nuget-org/trusted-publishing), so there's no long-lived API key sitting in the repository waiting to leak. Each release gets a [GitHub release](https://github.com/stphnwlsh/CleanLamdaFunction/releases) with generated notes.

## The docs

This site is built with [Starlight](https://starlight.astro.build) from the `website` folder and deployed to GitHub Pages whenever it changes on `main`. It also publishes an [`llms.txt`](https://stphnwlsh.github.io/CleanLamdaFunction/llms.txt), so your AI assistant can read the docs too. It still won't write the tests for you. Well, it might.
